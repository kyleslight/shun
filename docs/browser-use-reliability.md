# Browser interaction reliability

Shun uses the existing Chrome session through its extension. Browser work opens in a background tab by default. Showing a tab is an explicit action for a user request, never an automatic way to recover from a failed input.

## Findings

An investigated conversation received a disconnected response from `browser_tabs`, then switched to scripts that repeatedly launched a visible browser with a separate profile. The recorded response establishes disconnection, but does not establish whether the extension was absent, disabled, or temporarily unreachable. The scripts navigated back to the same form, identified unnamed inputs by their position, and reported success when a call returned without an exception. That allowed a language value to reach the location field and repeated submissions to encounter the same validation errors.

A later real login regression exposed a different failure: Chrome refused debugger attachment with `Cannot access a chrome-extension:// URL of different extension`. Reporting that denial as transient disconnection caused repeated reads to fail. The extension now distinguishes it and reads the website’s top frame through `chrome.scripting` in an isolated world. It reuses the same observer, action guards, and field verification. Isolated-page refs carry a separate prefix so a numeric ref from the debugger channel cannot accidentally identify a different page control after a transport change. The form and action boundaries accept those refs consistently. It does not inspect other extension frames, and reports visible embedded frame titles and the observation limitation. Embedded verification can be pending even when the main document has no error.

The built-in tools also had two gaps: batch filling did not verify resulting field values, and the background action branch could fall through into native input after already performing its page-side action. Both are addressed at the browser tool boundary.

## Practices adopted

- **Observe, bind, act, verify.** Use a current control ref and its exact accessible name for batch fields. Reject missing, renamed, disabled, or readonly targets before modifying the batch. Check focus before clearing and before inserting native input.
- **Keep identities stable and secrets hidden.** Input values never become accessible names. Mask credential values and omit them from fingerprints. Observe custom controls only from interaction evidence such as roles, focusability, or click handlers. Include region, destination, offscreen state, and an obstruction at the center in the reading, so a dialog can be addressed before an attempted blocked click.
- **Verify the result.** Read the actual native control value without returning that value from the verification call. Native select values can differ from their displayed labels, and masked input values cannot reliably be verified from accessibility text. Surface invalid, readonly, selected, expanded, and autocomplete states in observations.
- **Distinguish a query from a choice.** A custom autocomplete query is not a committed selection. Stop the batch and return fresh options for an explicit named choice. `select` is for native select controls; custom dropdowns require an observed option.
- **Preserve progress.** Skip values already confirmed, stop on a mismatched value, navigation, another changed field, validation failure, or uncertain response, and return completed, remaining, and uncertain refs. Do not automatically replay actions or submit as part of a fill batch.
- **Reduce model round trips.** Fill known ordinary fields in one tool call, with local verification between fields. The existing bounded fast tool handles routine subgoals using current observations; the main model handles ambiguous state. Use state-based settling instead of long fixed sleeps.
- **Preserve the user's workspace.** Background operations never automatically select a tab or focus a window. Report page-side input explicitly, and return a limitation when a control cannot work in the background. A disconnected tool attempts connection recovery and then reports a blocker; it does not prescribe a replacement browser profile or visible script-driven browser.

These rules guide tool use. General shell access is not an OS browser isolation boundary. No command-text classifier was introduced to enforce browser access.

## Sources and tradeoffs

- [Chrome scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting) and [debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger): distinguish browser access boundaries, and use a scoped isolated website context when debugging is unavailable.
- [Playwright locators](https://playwright.dev/docs/locators): locate controls through roles, names, and labels, with a current element at action time.
- [Playwright actionability](https://playwright.dev/docs/actionability): verify visibility, stability, event reachability, and editability; use assertions to establish results.
- [Playwright best practices](https://playwright.dev/docs/best-practices): user-facing contracts and web-first assertions rather than brittle selectors and immediate checks.
- [Stagehand speed optimization](https://github.com/browserbase/stagehand/blob/main/packages/docs/v3/best-practices/speed-optimization.mdx): observe multiple targets once, then execute explicit actions without a model decision for each field.
- [Stagehand prompting practices](https://github.com/browserbase/stagehand/blob/main/packages/docs/v2/best-practices/prompting-best-practices.mdx): discover specific controls before acting.
- [Browser Use session implementation](https://github.com/browser-use/browser-use/blob/main/browser_use/browser/session.py): persistent browser sessions and lifecycle management, rather than launching a browser for each action.

Shun adopts the applicable principles in its existing extension and tool interfaces. It does not import another agent loop, blindly retry submissions, guess semantic equivalents for ambiguous fields, or mutate third-party pages to reduce DOM complexity. A custom widget requiring trusted foreground input may still need explicit user involvement; silent simulated input is not reported as trusted input.

## Delayed operations and connection changes

An interrupted connection now retries observation calls only. Input, clicks, navigation, downloads that start an action, and tab creation are not resent after losing an acknowledgement. A queued isolated-page operation carries an execution deadline, so Chrome cannot apply expired input after Shun has reported an uncertain outcome. Injection and action phases have bounded waits and identify the phase that did not answer. Settling observations also honor their deadline.

A field batch checks the control's actual value before writing, including masked fields. A repeated replacement input already present in the page returns without focusing or sending another input sequence. A fresh read can resume a released task-owned session only when that identity was observed on the current extension connection and no other task owns the tab. Old control refs do not regain permission to act merely because a session was released; unknown identities still require a fresh claim.

Frame metadata is checked before exposing native refs. A foreign extension frame selects the scoped website channel before form input, including when initial attachment itself succeeds. This avoids changing reference channels halfway through the form.

The test harness previously used production discovery ports, allowing a real Chrome extension to connect to a test bridge. That is a test isolation failure, not a site pass. Unit bridge tests and the headless smoke now use ephemeral ports known only to the test connection. The isolated smoke passed after this correction; three verified fields took about 574 ms in that measured run. The test that accidentally used the real profile is excluded, and its temporary local pages were removed.

The actual Shun image viewer was also checked against two existing images in one conversation: Left selected the previous image, Right restored the original, and a click in the top blank strip closed the viewer.

## Coordinate and asynchronous-state regressions

A real native fallback exposed a capture/input mismatch on macOS: a desktop-independent child-window capture included its larger Chrome parent, then preserved the parent's aspect ratio in the child dimensions. The result included browser chrome and a black margin while normalized input used the child's listed rectangle. The driver now captures that same rectangle through a display-bound window filter, with an explicit source rectangle and no child windows or shadows. Windows crossing display boundaries are refused rather than returning ambiguous coordinate geometry. See Apple's [stream dimensions](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/preservesaspectratio) and [content filter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter) contracts.

In a bounded Shun-driven regression, a fresh corrected native screenshot followed by one coordinate click opened the actual account menu. Chrome text independently proved the name, email and Logout, and the original selected tab and Shun foreground were restored. This establishes the tested coordinate mapping, not universal model grounding accuracy. A later full workflow still made model/targeting mistakes and remains a failed speed/rework sample.

The native observation path now tracks bounded Document/Fetch/XHR request IDs started around an action, waits while they remain pending, and reports loading when they outlast settling. It retains no request URL, body or headers; streams and expired traffic cannot hold observations indefinitely. The real smoke checks a delayed request and requires confirmed resulting content or a loading state, without replaying the click.

Small image-only controls with pointer styling and labelled images are now observable under that image label, including delegated handlers on figures and wrappers. Static illustrations remain excluded from the interactive registry. A real isolated-page fixture proves that a labelled delegated profile opens exactly once.

The first real named-avatar test exposed a further activation error: both an outer figure and its inner span were exposed under the same name, but the handler belonged to the inner span. Clicking the outer element directly does not run a descendant handler. Scoped page clicks now dispatch to the already hit-tested innermost element, with the observed point, and bubble exactly once as physical pointer input does. Image-wrapper enumeration selects the innermost direct image/picture wrapper. The nested real-browser fixture binds its handler to that inner wrapper so an incorrect outer-only dispatch fails.

A subsequent real background observation with the revised enumeration found one avatar named Kyles (instead of the outer/inner duplicate). Its account menu was already open, so that sample verifies enumeration and current identity only; it is not counted as a successful opening click. The new controlled full workflow runs in an independent normal-UI task so prior geometry-only instructions and long test transcripts do not determine its behavior.

## Final observation and coordinate corrections

An earlier revision allowed eight seconds for isolated-page observations but only two for input. The subsequent visible Microworkers cycle showed that ordinary background observer injection and input could exceed that input cap; this revision was not accepted as fluent. A deterministic slow-read test completes after five seconds, while delayed queued input is still rejected. Background actions track bounded in-flight document/fetch/XHR requests when the debugger transport supports them, so a quiet DOM alone does not establish completion. The page-only transport reports its narrower observation boundary.

The real site's nested avatar exposed a separate event-target issue: a handler on an inner image wrapper does not receive an event dispatched only to its outer wrapper. The observer now prefers the innermost interactive wrapper, and synthetic input dispatches once to the actual hit-tested descendant, bubbling normally. The real extension smoke checks an inner delegated handler and verifies one activation. A subsequent actual PeoplePerHour cycle opened the current account menu through one webpage avatar click, with current name, email and Logout as evidence.

Native window screenshots now use the same screen rectangle as native input. A previously captured larger parent window included extra toolbar space, invalidating normalized click coordinates. A real Shun test used one coordinate from the corrected window screenshot to open the account menu and verify identity. This is a tested coordinate contract, not a guarantee that every model-selected target will be accurate.

The latest complete PeoplePerHour cycle took 250.123 seconds and 23 tools, with one logout, one verified field batch and one login submission. It restored the original selected tab and foreground app. It still encountered two read timeouts before the final observation-deadline reload and required desktop intervention. It is a completed functional cycle, not a fast, error-free or fully background acceptance pass. The failed and cancelled attempts remain in the local audit.

Page-only observations disclose synthetic delivery and the unavailable native keypress, scrolling and upload actions before a caller attempts them. Refs are opaque strings: a current `p:3` must never be shortened to `3`, and a returned current page supersedes refs from an earlier transport. The batch boundary stops safely if a transport changes after input; that stop does not grant permission to guess how an earlier ref maps to the new channel.

Verification of a submitted action must be read-only. A second HTTP POST is another submission, even if the model calls it a confirmation. A local negative-path model test exposed exactly that mistake after a single webpage click, and remains a failed sample. Guidance now states the boundary explicitly, including across browser, native input and shell HTTP routes. This is model guidance, not a shell-command classifier or an OS isolation guarantee.

The fixed ten-site regression separates completing an authentication cycle from completing it without rework. A blocked verification, missing credential, incomplete identity check, tool failure, wrong field, or unintended foreground action does not pass. Earlier successful individual cycles do not establish the ten-site result.

That regression exposed discarded tabs whose ownership claim unnecessarily waited for the renderer. Claiming now checks Chrome's tab metadata; observations explicitly disclose an unloaded document. An explicit navigation uses Chrome's tab API and can restore that document without activating it or replaying a form. A same-destination request only preserves an already loaded document; an unloaded one still needs the explicit navigation.

It also exposed screenshots that never completed while the accessibility text remained readable. Screenshot capture now has its own bounded deadline and preserves the successful text observation with an explicit limitation. It never selects the tab to obtain a screenshot. Display brackets around refs are normalized without adding or removing a channel prefix; a stopped form only returns still-current refs as actionable, and separately identifies historical fields that require rebinding.

Native accessibility observations now disclose depth truncation and default to the supported maximum depth. A shallow tree of browser toolbar controls cannot establish that a website control is absent. Authorized native fallback selects the exact owned browser session before reading the native UI; guessing a position in the tab strip is not a recovery strategy.

An authorized foreground switch returns the previously selected Chrome tab and, when native control is configured, the previously foreground application. The caller must retain the first bookmark for the whole intervention and restore that application after restoring the tab. Selecting a Chrome tab alone does not restore the user's foreground work.

A sign-in popup can close normally after returning to its original page. Reading a known, task-owned closed session returns `observation_status: closed`, no controls, and an explicit instruction to inspect the original page. It does not reopen the popup, update page evidence, infer authentication success, or grant action authority to a closed session. Other tasks cannot read that session through this path.

Connected mailbox search and message reading are directly available when that integration is enabled; mail mutations remain separately discoverable. An offline webmail tab does not establish that the connected mailbox is unavailable. Verification mail must match the requested site, account and current attempt; older unread mail and unrelated verification codes are not substitutes.

A real accelerated login exposed a handoff mismatch: fast DOM control 9 was mistaken for debugger node 9. Fast observations now use a distinct non-actionable display namespace, and the tool obtains one ordinary current reading before returning a completed or escalated DOM subgoal. This removes an extra model round trip while supplying valid ordinary refs. If that read fails, the tool preserves the diagnostic evidence without replaying input or converting identities. The regression checks deliberately use different DOM and debugger IDs for the same named control.

Default model-facing browser observations now retain a compact set of fields, alerts, dialogs and controls with bounded page text. An explicit `detail="full"` requests the expanded bounded reading. Omitted content is disclosed; the actual browser snapshot, field verification data, persisted evidence and canonical transcript are not pruned or rewritten. Native controls use short opaque reading handles bound to their window and controller instance. The driver still validates the original control identity before input; a newer reading or controller restart cannot reassign an old handle.

## Repeated observation cost

Historical experiment, superseded by the quality-preserving policy below: the automatic observation projection has been removed. Its offline size reductions are not current product behavior.

The Manus cycle spent 37.143 seconds inside tool executions out of 297.112 seconds elapsed. The remaining 259.969 seconds covered model responses and time between tools; this does not isolate server inference from every other delay. Its reported context grew above 84,000 tokens. Reducing local click latency alone cannot establish a fluid workflow.

The enabled browser capability now registers an inference-only context projection through the existing extension hook. The runtime boundary only accepts generic extension factories; it contains no browser policy. Each browser session and native window retains two to nine latest readable observations; tab inventories retain one to four. Completed batches of eight page readings or four inventories become fixed historical summaries. Adding a reading within a batch preserves the previous model-input prefix, avoiding the per-turn cache invalidation caused by a sliding cutoff. Older page/control dumps become explicitly historical summaries, with no actionable stale refs or screenshots. Action receipts, stopped form batches, failed tool results, and unique diagnostics are preserved. Exact duplicate diagnostic entries can rely on their later copy; old signed destinations retain origin/path metadata rather than a navigable truncated URL. Canonical conversation records, UI events, assistant messages, and user messages are unchanged.

The earlier sliding-cutoff experiment on the preserved Manus transcript reduced text from 197,184 to 52,469 characters (73%); on Indie Hackers from 200,949 to 85,143 (58%); on Microworkers from 62,666 to 43,289 (31%). These are historical offline context-size measurements for the earlier policy, not measurements of the current batch policy or task speedups. The subsequent real Microworkers cycle still took 231.830 seconds and required extra reads, so it did not pass fluency acceptance. Provider-boundary contracts verify both unchanged saved tool evidence and stable projected prefixes between batch boundaries.

The current [Browser Use parameter documentation](https://docs.browser-use.com/open-source/customize/agent/all-parameters) supports bounded model history and multiple actions per step, while [Stagehand's deterministic workflow guide](https://github.com/browserbase/stagehand/blob/main/packages/docs/v3/best-practices/deterministic-agent.mdx) identifies repeated inference as an automation cost and describes cached workflows. The earlier experiment applied bounded historical observations; that projection has since been removed. Verified field batches remain, and deterministic workflow caching is not implemented or claimed.
